# 云扫墓小程序 · 发布清单

更新：2026-11-14。代码已具备第 1 阶段功能；下表是从「开发者工具里能跑」到「微信里能搜到、能分享」之间必须由公司办理的事项。标「待核实」的以微信公众平台后台实际显示为准。

## 1. 阻塞上线的事项（按办理顺序）

| # | 事项 | 为什么必须 | 负责 / 周期 |
| --- | --- | --- | --- |
| 1 | **用企业（或个体工商户）主体注册小程序** | 小程序备案要求组织主体；带用户留言（UGC）的小程序个人主体会被驳回；小程序注册后主体不能迁移，个人号无法再转成公司号 [1][2][3] | CEO / 1–3 天 |
| 2 | **微信认证** | 不认证无法开通微信支付等能力（第 4 阶段需要）；认证费用以后台为准 [4] | 1–5 工作日 |
| 3 | **选服务类目**（待核实） | 官方「祭扫」类目要求主体机构类型为**机关**，企业选不了 [5]。需在后台为「纪念 / 生活服务 / 工具」类找可选类目；因有留言功能，审核可能要求社交类目并配置内容过滤 [2] | 提交后 1–3 工作日 |
| 4 | **小程序备案** | 自 2023-09-01 起，未上架的小程序必须完成备案才能上架 [6]；通信管理局审核通常 3–20 工作日 [1] | 2–4 周 |
| 5 | **接口域名 ICP 备案 + HTTPS** | request / socket 合法域名必须是 HTTPS、已 ICP 备案的域名，不能是 IP 或未备案域名 [7]。`*.supabase.co` 不能用 | 与 4 并行，约 2–3 周 |
| 6 | **后端迁到国内或加国内代理**（见第 3 节） | 有了备案域名才能配置合法域名；项目定位为国内部署 | 研发 3–8 人日 |
| 7 | **接入微信内容安全** | 留言、称呼、墓志铭是用户生成内容，审核会检查是否有内容过滤 [2]。需后端调用 `msgSecCheck`（需要用户 openid → 增加 `wx.login` + `code2session`） | 研发 1–2 人日 |
| 8 | **用户隐私保护指引** | 后台按实际填写：用户输入的纪念信息、剪贴板（粘贴邀请链接） | 0.5 天 |
| 9 | **隐私政策 / 用户协议正式版**（PRD D-08） | 现为占位文本 | 法务 |
| 10 | **真机测试**（A1-17、A1-20） | iOS、安卓各至少 1 台，记录机型与帧率 | 研发 / 测试 1 天 |

## 2. 上线后的阶段对资质的额外要求

| 阶段 | 需要 |
| --- | --- |
| 第 3 阶段 远方回音（AI 纪念回信） | 小程序需开通「深度合成」类目：个人主体不开放，需提供技术主体的算法备案 + 双方合作协议 [8]；且算法备案主体必须与签约主体一致，否则驳回 [9]。PRD D-02、D-03 |
| 第 4 阶段 纪念服务（付费） | 微信支付需认证 + 商户号；虚拟商品走小程序虚拟支付（iOS 有特殊规则），PRD D-04、D-05 |

## 3. 后端国内部署：三个方案

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| A. 国内代理 | 国内云服务器 + 备案域名，反向代理 HTTPS 与 WebSocket 到现有 Supabase | 最快，代码几乎不改（只改 `config.js`） | 数据仍在新加坡，涉及个人信息出境评估；跨境延迟与稳定性一般；只适合过渡 |
| B. 国内云自建（**建议**） | 腾讯云 / 阿里云国内地域：PostgreSQL + 把 `api` 移植为 Node 服务 + 自建 WebSocket 广播；55 座墓数据迁入 | 数据在境内，延迟低，表结构与接口不变 | 研发约 5–8 人日；需要运维 |
| C. 微信云开发 | 迁到云开发数据库 + 云函数，实时用数据库监听 | 免域名配置，免运维 | 要重写数据层与实时层；与网页版共享数据变复杂 |

## 4. 代码侧上线前要改的地方

1. `project.config.json`：`appid` 改成正式 AppID。
2. `config.js`：`apiBase`、`realtimeUrl` 改成备案域名；`webOrigin` 改成网页版正式域名。
3. 后台「开发管理 → 服务器域名」：request、socket 各填一个备案域名。
4. 后端：执行 `backend/migrations`，部署 `backend/functions/api` v2，并设置 `YUNSAOMU_AUTO_APPROVE_MS=0`。
